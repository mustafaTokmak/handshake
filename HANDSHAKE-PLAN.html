Handshake — original project plan

Historical proposal, 19 September 2026. Restored from the Handshake section of the archived idea-panel report. This plan describes protocol discovery and adapter generation. The current application focuses on shipment recovery after an uncertain request outcome; this document is not a specification of the implemented application.

Two systems that have never agreed on a protocol complete one job

User and pain. A developer connecting a warehouse export to a workshop's material-request system has endpoints and examples, but incomplete operational documentation. Both speak JSON; they disagree about identifiers, quantities, pagination, and the order in which an object must be reserved and consumed. Writing the mapping is easy after someone has discovered those details. The product is an agent that does that discovery through bounded experiments, creates an executable adapter, and completes a requested transfer. This is a proposed user need, not market validation.

Autonomous mechanism. Give the agent two local HTTP services, a short task such as “allocate 18 washers from these stock lots,” the exposed documentation, and an experiment budget. It chooses which endpoint to inspect, constructs probes that distinguish competing interpretations, runs them in a disposable test namespace, and updates an explicit contract. It generates a small adapter, executes it, reads actual failures, and revises once or twice. The end state is 18 units allocated in the destination with corresponding inventory consumption and matching source IDs. Python verifies conservation, counts, and duplicate handling. Gemini handles incomplete documentation and choosing informative experiments; Pydantic describes probes, observed evidence, and the adapter contract. Modal can isolate generated adapter execution, but is not required for HTTP concurrency.

The crucial boundary: the agent cannot read the services' implementation or fixture configuration. The evaluator can. Otherwise this becomes ordinary code translation dressed as discovery. Unit semantics must be discoverable from documentation or observations, never guessed.

Three-minute demo. At 0:00 show stock on the left and an empty destination allocation on the right. An ordinary schema-matching adapter fails visibly because matching field types did not establish quantity semantics or the reservation sequence. At 0:25 start Handshake; show two or three actual probes and the evidence each returned. At 1:05 the first executable transfer completes. At 1:25 an audience member changes one advertised supported protocol behavior: rename an identifier field, change an exposed lot-size field, or turn on overlapping pagination. They can enter the field name or lot size themselves; do not constrain them to a secretly preselected string. At 1:40 the next task encounters the new response, re-probes, adjusts the adapter, and attempts another transfer. At 2:30 show requested versus delivered units, unique IDs, and the runnable adapter. If adaptation fails, show the failure and its last observed evidence. Never manufacture a successful delivery.

Why a script/chat wrapper is insufficient. A handcrafted adapter solves one known contract. A chat response can propose a plausible adapter without running either side. Handshake must choose experiments, distinguish plausible mappings from observed behavior, execute, and respond to a contract change. But a deterministic schema matcher with protocol heuristics is a serious competitor, not a strawman: if it handles all supported changes equally well, the agent added little.

8.5-hour MVP. Three people: one owns the two tiny services and independent checker; one owns the probe/adapter loop; one owns the two-board display and rehearsal. Hour 0–1: kill test. Hours 1–3: one transfer through the real HTTP loop, reset, evidence store. Hours 3–5: two additional protocol variations and bounded adapter revision. Hours 5–6.5: UI and real intervention control. Hours 6.5–8.5: held-out combinations, failure handling, labelled recording, rehearsal. Cut arbitrary URLs, authentication, browser automation, OpenAPI import, SAP claims, deployment to customer systems, and unlimited generated code. Support two small documented service families and a typed transformation format. If code execution isolation is not working, use a constrained adapter DSL rather than execute unrestricted model code on the laptop.

Hardest dependency and 60-minute kill test. The difficult part is obtaining useful evidence quickly, not JSON generation. A teammate privately selects one of four protocol configurations. Within 60 minutes of beginning the build, a minimal agent must complete two unseen transfers using only endpoint observations, including one requiring a second probe after its first hypothesis fails. Cap the run at eight probes and 45 seconds, explicit engineering targets rather than promised performance. If it merely reads the exposed hints and produces the same adapter as a schema matcher, narrow the claim or reject the idea. Do not spend the afternoon disguising a static mapping as discovery.

Baseline, falsification, and risks. Compare a field-name/type matcher plus sensible pagination/deduplication heuristics, and an ordinary one-shot model-generated adapter, using identical visible documentation and budgets. A manually written correct adapter is the functional reference. Measure successful complete transfers, incorrect transfers, probe count, latency, and human corrections across separately authored configuration combinations. If the agent does not improve complete-task success over the heuristic baseline, or requires substantial human interpretation per job, its proposed advantage is falsified on this testbed. The largest risk is authoring a world that flatters your own hypothesis vocabulary. Keep the generator/evaluator configuration private from the agent and ask a different teammate to author held-out combinations. A local prototype establishes integration behavior, not broad enterprise compatibility.

Differentiation. This is neither ChangeProof's patch tournament nor UI Archaeologist/RetroAgent's video-to-browser replay. It learns an operational contract by acting on a black box, then creates the bridge. It does not intercept another agent, undo its work, negotiate prices, or claim that types prove correctness.
